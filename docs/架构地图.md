# ClaudeNeko 架构地图

> 目的：改代码前先看这张地图，知道「改一个函数会影响谁」「共享状态有几个写入口」，
> 避免"修一个地方、弄坏另一个地方"。
> 维护：任何新增/改动模块或共享状态时，顺手更新本文件。

## 0. 一句话架构

Node 零依赖后端（直接驱动本机 Claude Code CLI）+ React 前端。两条驱动路：
- **聊天（c2web 模式）**：常驻 pty 注入 + jsonl 轮询（transcript）→ store 镜像 → WS 推送
- **独立子进程**：`claude -p`（claudeRunner，媒体确认/历史摘要用），与聊天主流程隔离

## 2. 依赖关系

```
server.js ──→ settings / sessionStore / claudeRunner / mediaGen / ptyHost
           │    transcript / util / busyLock / bus
           ├──→ routes/system（→ balance）
           ├──→ routes/media（→ mediaStore / util / mediaGen / zip）
           ├──→ routes/export（→ util / zip）
           ├──→ routes/search（→ util）
           ├──→ routes/stats（→ util）
           ├──→ routes/sessions（→ claudeRunner / vision / docText / mediaUnderstand
           │                      / mediaStore / util / busyLock）
           ├──→ routes/terminal（→ ptyHost / transcript / store）
           └──→ routes/remote（→ remote / pairing）

lib 之间无横向依赖（各管各的）；共享状态通过 server.js 集中创建后以 ctx 注入 routes。
事件总线（Phase2）：ptyHost / transcript 只 emit（pty:exit / transcript:*），server.js 订阅做业务；
新增事件登记 lib/bus.js 事件字典。
```

**⚠ 原则：lib 之间不互相 require**（ptyHost 不碰 transcript，mediaGen 不碰 ptyHost）。
跨模块协作必须经 server.js 显式接线（或 bus 事件）。破坏这条 = 引入隐式耦合。

## 3. 共享状态清单（改前必查）

| 状态 | 谁读 | 谁能写（唯一写入口） |
|---|---|---|
| `busy` + `busyTimers`（会话在途锁+5min兜底timer） | sessions.js 查询 session.busy | **仅 busyLock**（acquire/release） |
| `session.claudeSessionId` | ptyHost.ensure / transcript.ensure / terminal.ensure | **仅 transcript.onSessionIdDiscovered**（server.js 回写） |
| pty `rec.ready`（就绪态） | ptyHost 内部 | **仅 ptyHost**（becomeReady；外部信号=markReady） |
| transcript `pollers` Map | transcript 内部 | **仅 transcript**（ensure/release/releaseAll） |
| terminal `clients` / `termBufs` | terminal 内部 | **仅 terminal**（broadcast/setTermBuffer/clearTermBuffer） |
| media 生成任务（gen_tasks） | mediaGen 内部 | **仅 mediaGen**（queryTask/cancelAll） |
| store（会话/消息） | 所有 routes | **仅 sessionStore**（create/update/append/remove/read） |

**规则：任何共享状态，写入口只能有一个模块。新状态照此登记。**

## 4. 口头契约（必须显性遵守，不许靠记）

1. **busy 由 assistant 事件 / 5min 兜底 / cancel / force-stop / pty 退出释放**——统一走 `busyLock.release()`（幂等）
2. **claudeSessionId 归属权只由 transcript 写**（server.js onSessionIdDiscovered）；mediaClaude 不得回写
3. **mediaClaude 必须独立会话**（不传 claudeSessionId、cwd 用独立目录）——避免与常驻 pty 并发写同一 jsonl
4. **assistant 事件释放锁时清 5min timer**（H3）——busyLock.release 已内建，新代码不许绕过
5. **pty 退出不释放 transcript**（防 emitted=0 全量回放重复）；transcript 只在会话删除时 release
6. **transcript 事件 → store 是唯一渲染源**；前端乐观气泡只做显示，不写 store
7. **node-pty 未加载时降级**：终端功能不可用，聊天必须报错而非假装可用

## 5. 改前查调用方清单（每次动手前必过）

- [ ] ③ 会不会破坏 §4 的口头契约？
- [ ] ④ 前端是否有对应调用（改后端接口时）？
- [ ] ⑤ 改完跑 `npm run regression`（快速版 `npm run regression:fast`）——覆盖主链路全项
