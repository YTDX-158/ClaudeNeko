四、架构与文件改动
链路：claude 要权限 → PermissionRequest hook → POST server /api/permission/request
     → WS 广播 → 前端卡片 → 用户点 /api/permission/respond → hook 得决定 → claude 继续
改动面：
- server/routes/permission.js(新)：request 挂起队列 + respond 幂等 + 超时 + 会话清理(N2)
- server/lib/permissionHook.js(新，或独立 .cjs)：瘦转发器，读 stdin → POST → 等 → 输出协议 JSON
  try/catch 全分支：连不上 server 立即输出空 → claude 原生问（N3 优雅降级）
- server/ptyHost.js：spawn claude 显式传 --permission-mode（按档：①②→default ③→bypass）
- 前端 PermissionCard.jsx(新)：卡片 + 3 按钮 + 危险操作红警样式 + 等待态
- 设置页：全局三档单选 + "已记住规则"管理
- 配置注入：ClaudeNeko 启动时向 ~/.claude/settings.json 合并注入 PermissionRequest hook
  （保留用户 PreToolUse；记录加的键，升级/卸载清理——B8 路径失效要刷新指向）

五、状态机设计（含故障雷解法——工程 60% 复杂度在这）
请求状态：NEW→PENDING→(allow/deny/canceled)
- N1【刷新丢卡片】A 等待中用户刷新/重连 → server 存挂起队列，前端重连自动重放未决卡片
- N2【中断泄漏】pty 会话被杀/停止 → server 清理该会话所有 pending(当 cancel 通知 hook 退出)，防泄漏
- N3【hook 崩/连不上 server】hook try/catch 全分支 + 快速失败输出空 → claude 原生，绝不无限挂
- N4【多端同会话】requestId 幂等：第一次响应生效其余忽略，全端广播同步
- N5【切会话/停止取消 pending】状态机支持 cancel，会话切换清理
- N6【并发请求】requestId 逐个处理，卡片顺序清晰
- 危险操作卡片红色警示（防无脑点"以后都行"→ 悄悄 bypass）
- respond 接口带共享密钥（hook↔server），防本机恶意程序冒充允许
- claude 版本不支持 hook → 启动探测，降级提示（不静默失效）
- 链路异常前端提示"权限通道异常，已让 Claude 原生询问"
