# ClaudeNeko 安全修复与媒体台账设计

## 背景与事实源

- 唯一事实源是公开仓库 `YTDX-158/ClaudeNeko` 的 `44225c4`。
- 本次工作位于独立克隆与分支 `codex-fixes-20260904`，不接触 Claude 持有的主工作区。
- 2026-09-03 审查包与本轮相关文件没有语义漂移；文件哈希差异来自 LF/CRLF 换行。
- Git 历史表明，媒体台账曾作为 `LogPanel.jsx` 存在；v2.4.3 加入服务器日志面板时覆盖了同名组件，但 `MediaLibrary` 引用与媒体台账 CSS 没有同步迁移。

## 目标与范围

本轮完成四个彼此可独立审查的变更：

1. 防止非 DeepSeek 凭据被余额查询发送给 DeepSeek。
2. 防止视频任务查询 API 暴露内部任务字段，尤其是 `apiKey`。
3. 防止远程代理的高危路径过滤被反斜杠绕过。
4. 恢复独立的媒体生成台账界面，不复用服务器日志面板。

本轮明确不做：

- 不改变 `gen_tasks.json` 的持久化结构；凭据落盘与跨重启恢复的取舍另行设计。
- 不重构 PTY、回合 generation、取消体系或媒体任务状态机。
- 不修改媒体台账后端结构和成本计算；成本显示为 `—`。
- 不合并、不发布版本，由用户最终决定。

## 方案比较

### 方案 A：小型纯函数边界 + 独立 MediaLedger（采用）

- 把密钥选择、任务 DTO、代理路径规范化做成可直接测试的生产函数。
- 保留现有业务流，只在输入/输出边界收紧行为。
- 从历史台账实现和遗留 CSS 中复用已验证的信息架构，但以新名称 `MediaLedger` 恢复，避免再次与服务器 `LogPanel` 冲突。

优点：变更局部、可写精确回归测试、容易逐项回滚。缺点：不解决凭据落盘等第二阶段问题。

### 方案 B：直接在现有函数内打补丁

代码行数更少，但关键判断藏在 HTTP handler 和闭包里，难以测试；媒体台账若直接写进 `MediaLibrary` 会继续扩大组件。

### 方案 C：趁机重构安全策略和任务模型

可一次解决远程能力模型、任务凭据与持久化，但范围远超本轮，回归面大，不采用。

## 详细设计

### 1. DeepSeek 余额凭据

新增纯选择逻辑：

1. 专用 `DEEPSEEK_API_KEY` 始终可用，进程环境优先于 settings。
2. 通用 `ANTHROPIC_AUTH_TOKEN` 只有在同一来源对象的 `ANTHROPIC_BASE_URL` 经 `URL` 解析后，协议为 HTTPS 且 hostname 严格等于 `api.deepseek.com` 时才可用。
3. 畸形 URL、子域名、用户名伪装或其他供应商地址均不得返回通用 token。
4. `/api/balance` 保留业务层本地来源校验；远程代理显式屏蔽该路径，使“仅本机”在代理场景也成立。

不对真实 DeepSeek 发测试请求；自动测试只验证凭据选择和路由策略。

### 2. 视频任务公开 DTO

新增 `toPublicTask(task)`，只返回前端实际使用的：

- `status`
- `mediaId`（存在时）
- `error`（存在时）
- `ts`（存在时）

`queryTask()` 的不存在、进行中、完成和失败路径最终都返回该 DTO；内部 watcher 继续使用闭包中的原任务对象，持久化行为不变。不得返回 `apiKey`、`baseUrl`、`prompt`、`sid`、`querying`、认领字段或锁字段。

### 3. 远程代理路径规范化

请求进入代理时，用与业务服务一致的 WHATWG `URL` 解析得到 pathname，再交给 `isBlocked()`。解析失败时按高危请求处理并返回 403，不把畸形路径转发。

测试至少覆盖：

- 标准 `/force-stop` 路径被拦截。
- 原始反斜杠 `/api/sessions/demo\\force-stop` 规范化为斜杠后被拦截。
- 普通聊天/媒体路径保持放行。
- `/api/balance` 被远程策略拦截。

### 4. MediaLedger

新建 `web/src/components/MediaLedger.jsx`，`MediaLibrary` 的 `log` tab 只渲染该组件；当前服务器日志 `LogPanel.jsx` 及设置页入口保持不变。

`api.js` 新增：

- `mediaLog()`：读取 `{ enabled, records, softMax }`
- `mediaLogDelete(body)`：删除记录，本轮 UI 只发送 `{ all: true }`
- `mediaLogEnabled(enabled)`：切换后续记录开关

组件行为：

- 首次切入 tab 自动加载，提供手动刷新。
- 展示记录开关、记录数量与软上限提示。
- 表格列为时间、类型、模型、提示词、参数、结果、文件、成本。
- 提示词单行省略并用 `title` 显示全文；失败结果用 `title` 显示错误。
- 文件列展示文件名和大小；成本本轮固定显示 `—`。
- 只有“清空记录”操作，发送 `{ all: true }`，不传 `delFile`，不删除媒体文件。
- 空态、加载态和错误态均在 tab 内显示，不关闭整个媒体库。
- 小屏幕允许表格横向滚动，不压坏媒体库布局。

## 错误处理

- API 请求失败必须显示可见错误，不静默伪装为空数据。
- 开关更新失败时恢复旧值并提示。
- 清空失败时保留现有记录；成功后本地清空并重新读取。
- DTO 投影对非对象输入返回 `{ status: 'not_found' }`，避免异常对象穿透。
- URL 规范化失败采用 fail closed。

## 测试与验证

仓库当前没有单元测试框架；使用 Node 内置 `node:test`，不增加测试依赖。

每个后端修复遵循红绿循环：先写会失败的行为测试并确认失败，再写最小实现并确认通过。测试覆盖凭据选择、任务 DTO 白名单和代理路径规范化。

媒体台账前端缺少 DOM 测试环境，本轮以 `npm run build` 作为自动化结构验证，并由 Claude 在真实浏览器中验证真实台账记录、开关、刷新、清空和响应式布局。

完成时运行：

- 新增 Node 单元测试
- `node --check`（变更的后端文件）
- `npm run build`
- 可启动本地服务时运行 `npm run regression:fast`；若环境缺少 Claude/本机配置，明确记录未验证项
